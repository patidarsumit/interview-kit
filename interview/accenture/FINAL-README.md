## Technical Questions They May Ask

Use these rapid answers.

### Angular Lifecycle

```text
Angular lifecycle hooks allow us to respond to component creation, input changes, view initialization, and destruction. Common hooks are ngOnInit, ngOnChanges, ngAfterViewInit, and ngOnDestroy. I usually use ngOnInit for initialization, ngOnChanges for input change handling, ngAfterViewInit for view-child related logic, and ngOnDestroy for cleanup like unsubscribing.
```

### Guard Vs Interceptor

```text
A guard controls route access, for example whether a user can open a route based on authentication or role. An interceptor sits in the HTTP request/response pipeline and is used for adding auth tokens, handling errors, logging, or global loading behavior.
```

### Reactive Forms

```text
Reactive forms are model-driven forms in Angular. They are useful for complex forms because validations, dynamic fields, nested form groups, conditional rules, and test cases are easier to manage in TypeScript.
```

### RxJS switchMap

```text
switchMap cancels the previous inner observable when a new value comes. It is useful for search, filters, and API calls where only the latest request result should be used.
```

### OnPush Change Detection

```text
OnPush improves performance by checking a component mainly when input references change, events happen, async pipe emits, or change detection is manually triggered. It works best with immutable data patterns.
```

### Lazy Loading

```text
Lazy loading loads feature modules or routes only when needed instead of loading everything at application startup. It improves initial load performance, especially in large enterprise Angular applications.
```

## WCAG Guidelines

```text
WCAG stands for Web Content Accessibility Guidelines. It helps make web applications usable for people with disabilities.

The four main WCAG principles are POUR:

Perceivable: users should be able to perceive content, such as text alternatives, labels, and good contrast.
Operable: users should be able to operate the UI, including keyboard navigation and visible focus.
Understandable: UI and forms should be clear, predictable, and helpful.
Robust: content should work well with assistive technologies like screen readers.

In Angular projects, I apply WCAG through semantic HTML, proper form labels, keyboard support, focus management, ARIA attributes only where needed, color contrast, accessible dialogs/dropdowns, and screen-reader-friendly error messages.
```

## Accessibility In Angular

```text
For accessibility, I check whether the page can be used with keyboard only, whether forms have proper labels and error messages, whether focus moves correctly in dialogs or dynamic screens, and whether screen readers can understand the component state.

For reusable components like dropdowns, modals, tables, and form controls, accessibility is very important because one issue can repeat across many screens.

I use tools like Lighthouse, Axe-style checks, and browser DevTools, but I also do manual keyboard testing because automated tools cannot catch everything.
```

## How Quality Gates Work

```text
A quality gate is a set of conditions that code must pass before it is accepted.

For example, a project may require no blocker or critical issues, minimum test coverage, limited duplicated code, no new vulnerabilities, and acceptable maintainability rating.

When code is pushed, CI runs build, tests, linting, and SonarQube scan. SonarQube compares the result against the quality gate.

If the gate passes, the pipeline can continue. If it fails, we review the issue, fix real problems, add tests if coverage is low, reduce duplication, or discuss exceptions only if there is a valid reason.

In my view, quality gates are useful because they stop quality from becoming subjective and help teams maintain consistent standards.
```
